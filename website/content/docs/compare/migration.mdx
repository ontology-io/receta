## Why Migrate?

**Before (Array.sort callback):**
```typescript vanilla
users.sort((a, b) => {
  if (a.department < b.department) return -1
  if (a.department > b.department) return 1
  if (a.salary > b.salary) return -1
  if (a.salary < b.salary) return 1
  return a.name.localeCompare(b.name)
})
```

**After (Compare module):**
```typescript
import { compose, ascending, descending, caseInsensitive } from '@ontologyio/receta/compare'
import * as R from 'remeda'

const sorted = R.sort(
  users,
  compose(
    ascending(u => u.department),
    descending(u => u.salary),
    caseInsensitive(u => u.name)
  )
)
```

✅ More readable  
✅ Type-safe  
✅ Reusable  
✅ Testable  
✅ Composable

## Step 1: Identify Sortable Fields

Find all `Array.sort()` calls in your codebase:

```bash
# Search for sort callbacks
grep -r "\.sort\((a, b)" src/
grep -r "\.sort\(function" src/
```

Document each sort's logic:
- What fields are being compared?
- What's the sort order (asc/desc)?
- Are nulls handled?
- Is it multi-level?

## Step 2: Replace Simple Sorts

Native `.sort()` changes the array in place. `R.sort` returns a sorted copy and leaves the original alone, so keep what it returns, and read the copy wherever the old code read the array afterwards.

### Pattern 1: Single Field Ascending

```typescript vanilla
// Before
numbers.sort((a, b) => a - b)
```

```typescript
// After
import { ascending } from '@ontologyio/receta/compare'
import * as R from 'remeda'

const sorted = R.sort(numbers, ascending(x => x))
```

### Pattern 2: Single Field Descending

```typescript vanilla
// Before
scores.sort((a, b) => b - a)
```

```typescript
// After
import { descending } from '@ontologyio/receta/compare'
import * as R from 'remeda'

const sorted = R.sort(scores, descending(x => x))
```

### Pattern 3: Object Property

```typescript vanilla
const users = [{ name: 'Alice', age: 30 }, { name: 'Bob', age: 25 }]

// Before
users.sort((a, b) => a.age - b.age)
```

```typescript
// After
import { ascending, byKey } from '@ontologyio/receta/compare'
import * as R from 'remeda'

const users = [{ name: 'Alice', age: 30 }, { name: 'Bob', age: 25 }]

const sorted = R.sort(users, ascending(u => u.age))

// Or use byKey for direct property access
const sortedByKey = R.sort(users, byKey('age'))
```

### Pattern 4: String Comparison

```typescript vanilla
// Before
names.sort((a, b) => a.localeCompare(b))
```

```typescript
// After
import { localeCompare } from '@ontologyio/receta/compare'
import * as R from 'remeda'

const sorted = R.sort(names, localeCompare(x => x, 'en-US'))
```

Reach for `localeCompare` here, not `ascending`. `ascending` compares with `<`, which puts `Zoe` before `adam`, so the order would change.

### Pattern 5: Date Comparison

```typescript vanilla
// Before
events.sort((a, b) => a.date.getTime() - b.date.getTime())
```

```typescript
// After
import { byDate } from '@ontologyio/receta/compare'
import * as R from 'remeda'

const sorted = R.sort(events, byDate(e => e.date))
```

## Step 3: Replace Multi-Level Sorts

### Pattern: Nested If Statements

```typescript vanilla
// Before
items.sort((a, b) => {
  if (a.priority !== b.priority) {
    return b.priority - a.priority // Higher priority first
  }
  if (a.status !== b.status) {
    return a.status.localeCompare(b.status)
  }
  return a.createdAt.getTime() - b.createdAt.getTime()
})
```

```typescript
// After
import { compose, descending, ascending, byDate } from '@ontologyio/receta/compare'
import * as R from 'remeda'

const sorted = R.sort(
  items,
  compose(
    descending(i => i.priority),
    ascending(i => i.status),
    byDate(i => i.createdAt)
  )
)
```

### Pattern: Ternary Chain

```typescript vanilla
// Before
products.sort((a, b) =>
  a.category !== b.category
    ? a.category.localeCompare(b.category)
    : b.rating !== a.rating
    ? b.rating - a.rating
    : a.price - b.price
)
```

```typescript
// After
import { compose, ascending, descending } from '@ontologyio/receta/compare'
import * as R from 'remeda'

const sorted = R.sort(
  products,
  compose(
    ascending(p => p.category),
    descending(p => p.rating),
    ascending(p => p.price)
  )
)
```

## Step 4: Handle Null Values

### Pattern: Nullish Coalescing

```typescript vanilla
// Before
users.sort((a, b) => {
  const aVal = a.lastLogin ?? new Date(0)
  const bVal = b.lastLogin ?? new Date(0)
  return aVal.getTime() - bVal.getTime()
})
```

```typescript
// After
import { ascending } from '@ontologyio/receta/compare'
import * as R from 'remeda'

const sorted = R.sort(users, ascending(u => u.lastLogin ?? new Date(0)))
```

### Pattern: Explicit Null Checks

```typescript vanilla
// Before
items.sort((a, b) => {
  if (a.value === null && b.value === null) return 0
  if (a.value === null) return -1
  if (b.value === null) return 1
  return a.value - b.value
})
```

```typescript
// After
import { ascending, byBoolean, compose } from '@ontologyio/receta/compare'
import * as R from 'remeda'

const sorted = R.sort(
  items,
  compose(
    byBoolean(i => i.value !== null), // false sorts first, so nulls lead
    ascending(i => i.value ?? 0)
  )
)
```

### Pattern: Numeric String Comparison

```typescript vanilla

```

```typescript

import { natural } from '@ontologyio/receta/compare'

const sorted = R.sort(files, natural(f => f.name))

```

## Step 7: Extract Reusable Comparators

Before:
```typescript vanilla
// Repeated in multiple places
function sortUsersByName(users: User[]) {
  return users.sort((a, b) => a.lastName.localeCompare(b.lastName))
}

function sortEmployeesByName(employees: Employee[]) {
  return employees.sort((a, b) => a.lastName.localeCompare(b.lastName))
}
```

After:
```typescript
import { ascending } from '@ontologyio/receta/compare'
import * as R from 'remeda'

// Reusable comparator
const byLastName = ascending((person: { lastName: string }) => person.lastName)

// Use everywhere
function sortUsersByName(users: User[]) {
  return R.sort(users, byLastName)
}

function sortEmployeesByName(employees: Employee[]) {
  return R.sort(employees, byLastName)
}
```

## Step 8: Parameterize Sort Direction

Before:
```typescript vanilla
function sortProducts(products: Product[], direction: 'asc' | 'desc') {
  return products.sort((a, b) => {
    const diff = a.price - b.price
    return direction === 'asc' ? diff : -diff
  })
}
```

After:
```typescript
import { ascending, descending } from '@ontologyio/receta/compare'
import * as R from 'remeda'

function sortProducts(products: Product[], direction: 'asc' | 'desc') {
  const comparator = direction === 'asc'
    ? ascending(p => p.price)
    : descending(p => p.price)

  return R.sort(products, comparator)
}
```

## Migration Checklist

For each `Array.sort()` in your codebase:

- [ ] Identify all fields being compared
- [ ] Determine sort order for each field (asc/desc)
- [ ] Check for null/undefined handling
- [ ] Look for string case handling
- [ ] Check if natural sorting is needed
- [ ] Identify if it's single or multi-level
- [ ] Replace with appropriate Compare functions
- [ ] Read the array `R.sort` returns, because it doesn't sort in place
- [ ] Test that sort order is identical
- [ ] Extract reusable comparators if repeated
- [ ] Update tests to use new comparators

## Common Pitfalls

### Pitfall 1: Expecting `R.sort` to Sort in Place

```typescript nolint
// ❌ R.sort returns a copy, so users keeps its old order
R.sort(users, byKey('age'))
renderTable(users)

// ✅ Keep the copy and read that
const sorted = R.sort(users, byKey('age'))
renderTable(sorted)
```

### Pitfall 2: Forgetting to Return from Arrow Functions

```ts nocheck
// ❌ Wrong
const comparator = ascending(x => { x.value })

// ✅ Correct
const comparator = ascending(x => x.value)
```

### Pitfall 3: Mutating During Comparison

```typescript
// ❌ Don't mutate in comparator
const withSideEffect = R.sort(items, ascending((x: Item) => {
  x.viewed = true  // Side effect!
  return x.priority
}))

// ✅ Pure extraction
const sorted = R.sort(items, ascending((x: Item) => x.priority))
```

### Pitfall 4: Wrong compose() Order

```typescript
// ❌ Wrong order (priority before status)
compose(
  ascending((x: Item) => x.priority),
  ascending((x: Item) => x.status)
)

// ✅ Correct (status before priority)
compose(
  ascending((x: Item) => x.status),
  ascending((x: Item) => x.priority)
)

// compose() applies in order: first has highest priority
```

### Pitfall 5: Comparing Different Types

```typescript
// ❌ Mixing types
ascending((x: Item) => x.date ?? 'never')  // Date | string

// ✅ Consistent types
ascending((x: Item) => x.date ?? new Date(0))  // Always Date
```

## Testing Your Migration

### Unit Test Template

```typescript
import { describe, it, expect } from 'bun:test'
import { yourComparator } from './comparators'
import * as R from 'remeda'

describe('Migration: Product sorting', () => {
  it('maintains same order as original implementation', () => {
    const products = [{ price: 20 }, { price: 10 }]

    // Original comparator
    const originalSort = R.sort(products, (a, b) => a.price - b.price)

    // New comparator
    const newSort = R.sort(products, yourComparator)

    expect(newSort).toEqual(originalSort)
  })

  it('handles edge cases', () => {
    const edgeCases = [{ price: 0 }, { price: 10 }, { price: 10 }]
    const sorted = R.sort(edgeCases, yourComparator)
    expect(sorted).toBeDefined()
  })
})
```

## Incremental Migration Strategy

1. **Start with leaf nodes** - Migrate simplest sorts first
2. **One file at a time** - Don't refactor everything at once
3. **Test thoroughly** - Ensure sort order is identical
4. **Extract patterns** - Create reusable comparators
5. **Document decisions** - Note any behavioral changes
