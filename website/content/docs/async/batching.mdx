## Batch Processing

### The Problem: Processing Large Datasets

```typescript
// DON'T: Process 10,000 payments all at once
async function processPayments(payments: Payment[]) {
  return Promise.all(payments.map(p => stripe.charges.create(p)))
  // Problems:
  // - Memory explosion
  // - API rate limits hit
  // - All-or-nothing failure
  // - No progress visibility
}
```

### The Solution: Controlled Batching

```typescript
import { batch, mapAsync } from '@ontologyio/receta/async'

async function processPayments(payments: Payment[]) {
  return batch(payments, (group) =>
    // batch hands over 100 payments at a time, mapAsync limits requests within them
    mapAsync(group, (payment) => stripe.charges.create({
      amount: payment.amount,
      currency: payment.currency,
      customer: payment.customerId
    }), { concurrency: 10 }), // 10 concurrent requests per batch
  {
    batchSize: 100,            // Process 100 at a time
    delayBetweenBatches: 1000  // Wait 1s between batches
  })
}
```

## Batch Function Overview

### Basic Usage

`fn` runs once per batch and receives the whole batch, which suits bulk APIs. You get one result per batch:

```typescript
import { batch } from '@ontologyio/receta/async'

// Simple batching
const results = await batch(
  items,
  async (group) => saveAll(group),
  { batchSize: 50 }
)

// Several batches at once
const results = await batch(
  items,
  async (group) => saveAll(group),
  {
    batchSize: 100,
    concurrency: 5
  }
)

// A pause between batches
const results = await batch(
  items,
  async (group) => saveAll(group),
  {
    batchSize: 100,
    delayBetweenBatches: 500
  }
)

// batch has no progress callbacks, so count inside fn
let completed = 0

const results = await batch(
  items,
  async (group) => {
    const saved = await saveAll(group)
    completed += group.length
    console.log(`Progress: ${completed}/${items.length} (${(completed/items.length*100).toFixed(1)}%)`)
    return saved
  },
  { batchSize: 100 }
)
```

### Type Signature

```typescript title="Signature"
function batch<T, U>(
  items: readonly T[],
  fn: (batch: readonly T[]) => Promise<U>,
  options?: BatchOptions
): Promise<Result<U[], BatchError>>

interface BatchOptions {
  batchSize?: number           // Items per batch (default: 10)
  concurrency?: number         // Batches running at once (default: 1)
  delayBetweenBatches?: number // Delay between batches in ms (default: 0)
}

interface BatchError {
  type: 'batch_error'
  batchIndex: number
  itemsInBatch: number
  underlyingError: unknown
}
```

A `delayBetweenBatches` above 0 runs batches one at a time and ignores `concurrency`. `batchIndex` is `-1` when the failed batch can't be identified: with a delay, or when `concurrency` covers every batch.

## Batch Size Optimization

### Finding the Right Batch Size

```typescript
// Rule of thumb: Start with these defaults and adjust
const defaultBatchSizes = {
  // API Calls
  externalApi: 100,      // Most APIs handle 100/batch well
  database: 1000,        // Databases can handle larger batches
  emailSending: 50,      // Email services often rate-limit

  // Data Processing
  imageProcessing: 10,   // CPU/memory intensive
  fileUploads: 5,        // I/O bound operations
  dataTransform: 5000,   // Pure computation can be large
}

// Adaptive batching based on processing time
async function adaptiveBatch<T, U>(
  items: T[],
  fn: (item: T) => Promise<U>
): Promise<U[]> {
  let batchSize = 100
  const results: U[] = []

  for (let i = 0; i < items.length; i += batchSize) {
    const batchItems = items.slice(i, i + batchSize)
    const startTime = Date.now()

    const batchResults = await Promise.all(batchItems.map(fn))
    results.push(...batchResults)

    const duration = Date.now() - startTime

    // Adjust batch size based on duration
    if (duration < 1000) {
      batchSize = Math.min(batchSize * 1.5, 500) // Increase
    } else if (duration > 5000) {
      batchSize = Math.max(batchSize * 0.5, 10)  // Decrease
    }
  }

  return results
}
```

## Delays Between Batches

### Rate Limit Compliance

```typescript
import { batch, mapAsync } from '@ontologyio/receta/async'

// Stripe: 100 requests per second
async function batchStripeCharges(charges: ChargeRequest[]) {
  return batch(charges,
    (group) => mapAsync(
      group,
      (charge) => stripe.charges.create(charge),

      batchSize: 100,
      delayBetweenBatches: 1000  // 1 second delay = 100 req/sec
    }

// SendGrid: 10,000 emails per hour
async function batchSendEmails(emails: Email[]) {
  const perBatch = 100
  const batchesPerHour = 10000 / perBatch // 100 batches
  const delayBetweenBatches = (60 * 60 * 1000) / batchesPerHour // ~36 seconds

  return batch(emails,
    async (group) => {
      const sent = await sendgrid.send(group)
      console.log(`Batch complete. Next batch in ${delayBetweenBatches}ms`)
      return sent
    },
    {
      batchSize: perBatch,
      delayBetweenBatches
    }
  )
}
```

### Exponential Backoff Between Batches

```typescript
async function batchWithBackoff<T, U>(
  items: T[],
  fn: (item: T) => Promise<U>,
  batchSize: number
): Promise<U[]> {
  const batches = chunk(items, batchSize)
  const results: U[] = []

  for (const [index, batch] of batches.entries()) {
    const delay = Math.min(1000 * Math.pow(2, index), 30000)
    if (index > 0) {
      await sleep(delay)
    }

    const batchResults = await Promise.all(batch.map(fn))
    results.push(...batchResults)
  }

  return results
}
```

## Polling Strategies

### Poll Function Overview

```typescript
import { poll } from '@ontologyio/receta/async'

// Poll until condition is met
const result = await poll(
  async () => {
    const job = await api.getJob(jobId)
    return job.status === 'completed' ? job : null
  },
  {
    interval: 1000,   // Check every 1 second
    timeout: 60000,   // Give up after 60 seconds
    maxAttempts: 100, // Or after 100 attempts
  }
)
```

### Type Signature

```typescript title="Signature"
function poll<T>(
  fn: () => Promise<T | null | undefined | false>,
  options?: PollOptions
): Promise<Result<T, PollError>>

interface PollOptions {
  interval?: number      // Time between checks (default: 1000)
  maxAttempts?: number   // Max number of attempts (default: 10)
  timeout?: number       // Max total time (no limit by default)
  shouldContinue?: (attempt: number) => boolean
  onPoll?: (attempt: number) => void
}

type PollError =
  | { type: 'max_attempts'; attempts: number }
  | { type: 'timeout'; elapsed: number }
  | { type: 'stopped'; attempt: number }
```

- `null`, `undefined` and `false` mean "not yet". Anything else, including `0` and `''`, stops polling and becomes the `Ok` value.
- If `fn` throws, `poll` rejects instead of returning an `Err`. Return failures as values, as [the examples below](#job-status-polling) do.
- `maxAttempts` defaults to 10, so raise it along with a long `timeout`, or the attempts run out first.
- The wait is `interval` every time. There's no backoff.
- After a timeout, `poll` returns, but the loop keeps calling `fn` until it runs out of attempts.

## Working with PollError

`poll` returns a `Result`, so you can tell the failure modes apart without exceptions:

### Real-World: CI/CD Job Monitoring with Result

```typescript
import { poll } from '@ontologyio/receta/async'
import { isErr } from '@ontologyio/receta/result'

type JobStatus = {
  id: string
  status: 'pending' | 'running' | 'success' | 'failed'
  result?: string
  error?: string
}

const monitorCIJob = async (jobId: string) => {
  const result = await poll(
    async () => {
      const response = await fetch(`/api/jobs/${jobId}`)
      const job: JobStatus = await response.json()

      if (job.status === 'success' || job.status === 'failed') {
        return job
      }
      return null // Keep polling
    },
    {
      interval: 5000,
      maxAttempts: 60, // 5 minutes max
      timeout: 300000,
      onPoll: (attempt) => {
        console.log(`Checking job ${jobId} (attempt ${attempt})`)
      }
    }
  )

  // Handle different error types
  if (isErr(result)) {
    if (result.error.type === 'timeout') {
      return { status: 'timeout', message: `Job timed out after ${result.error.elapsed}ms` }
    }
    if (result.error.type === 'max_attempts') {
      return { status: 'failed', message: `Max polling attempts (${result.error.attempts}) reached` }
    }
    return { status: 'stopped', message: 'Polling stopped' }
  }

  return { status: result.value.status, result: result.value.result }
}
```

### Real-World: Order Processing with Result

```typescript
import { poll, retry } from '@ontologyio/receta/async'
import { type Result, isErr, mapErr } from '@ontologyio/receta/result'
import * as R from 'remeda'

type Order = { id: string; status: 'processing' | 'complete'; total: number }

const waitForOrder = async (orderId: string): Promise<Result<Order, string>> => {
  // Poll with retry on network failures
  const pollRes = await poll(
    async () => {
      const res = await retry(
        () => fetch(`/api/orders/${orderId}`).then(r => r.json()),
        { maxAttempts: 2, delay: 500 }
      )

      if (isErr(res)) return null // Retry polling

      const order = res.value as Order
      return order.status === 'complete' ? order : null
    },
    { interval: 2000, maxAttempts: 30 }
  )

  return R.pipe(
    pollRes,
    mapErr(error => {
      if (error.type === 'max_attempts') {
        return `Order ${orderId} processing timed out`
      }
      return `Order polling failed: ${error.type}`
    })
  )
}
```

### Benefits

✅ **Discriminated error types** - Know exactly why polling failed
✅ **No exceptions** - Pure functional polling
✅ **Composable** - Chain with other Result operations
✅ **Full context** - Access attempts, elapsed time, etc.

## Polling Patterns

### Job Status Polling

```typescript
import { poll, type PollError } from '@ontologyio/receta/async'
import { type Result, err, flatten, ok } from '@ontologyio/receta/result'

// AWS Batch job monitoring
async function waitForBatchJob(
  jobId: string
): Promise<Result<JobResult, PollError | string>> {
  const finished = await poll(
    async () => {
      const job = await batchClient.describeJobs({ jobs: [jobId] })
      const status = job.jobs[0]?.status

      if (status === 'SUCCEEDED') {
        return ok({ jobId, status, output: job.jobs[0].container.output })
      }
      if (status === 'FAILED') {
        return err(`Job failed: ${job.jobs[0].statusReason}`)
      }

      return null // Still running
    },
    {
      interval: 5000,    // Check every 5 seconds
      maxAttempts: 720,  // Enough attempts to reach the timeout
      timeout: 3600000,  // 1 hour timeout
      onPoll: (attempt) => {
        console.log(`Checking job status (attempt ${attempt})...`)
      }
    }
  )

  return flatten(finished)
}
```

## Combining Poll with Timeout

### Time Limit Option

`poll` takes a `timeout` option, so there's no separate promise to race. Give it enough attempts that the timeout is what stops it:

```typescript
import { poll, type PollError } from '@ontologyio/receta/async'

async function pollWithTimeout<T>(
  fn: () => Promise<T | null>,
  pollIntervalMs: number,
  timeoutMs: number
): Promise<Result<T, PollError>> {
  return poll(fn, {
    interval: pollIntervalMs,
    maxAttempts: Math.ceil(timeoutMs / pollIntervalMs) + 1,
    timeout: timeoutMs
  })
}

// Usage
const result = await pollWithTimeout(
  async () => {
    const status = await checkJobStatus(jobId)
    return status.complete ? status : null
  },
  1000,
  30000
)
```

```typescript
async function exportUsersToCSV(
```

```typescript
interface EmailCampaign {

      batchSize: 100,            // SendGrid batch limit
      delayBetweenBatches: 1000  // Rate limit compliance
    }
```

```typescript
async function processLargeDataset(items: Item[]) {

async function processLargeDataset(items: Item[]) {
```

## Error Handling in Batches

### Fail Fast vs. Continue on Error

```typescript
// Strategy 1: Fail fast
async function batchFailFast<T, U>(items: T[], fn: (item: T) => Promise<U>) {
  return batch(
    items,
    // unwrap throws, which is what batch counts as a failure
    async (group) => unwrap(await mapAsync(group, fn)),
    { batchSize: 100 }
  )
  // The first failed batch stops the rest
}

// Strategy 2: Collect errors, continue processing
async function batchContinueOnError<T, U>(
  items: T[],
  fn: (item: T) => Promise<U>
): Promise<{ results: U[]; errors: Array<{ item: T; error: unknown }> }> {
  const results: U[] = []
  const errors: Array<{ item: T; error: unknown }> = []

  await batch(items,
    (group) => mapAsync(group, async (item) => {
      const result = await tryCatchAsync(() => fn(item))
      if (isOk(result)) {
        results.push(result.value)
      } else {
        errors.push({ item, error: result.error })
      }
    }),
    { batchSize: 100 }
  )

  return { results, errors }
}
```

### Retry Failed Items

```typescript
type BatchFailure = { message: string; failedItems: unknown[] }

async function batchWithRetry<T, U>(
  items: T[],
  fn: (item: T) => Promise<U>,
  maxRetries = 3
): Promise<Result<U[], BatchFailure>> {
  let currentItems = items
  let allResults: U[] = []

  for (let attempt = 0; attempt <= maxRetries; attempt++) {
    const { results, errors } = await batchContinueOnError(currentItems, fn)

    allResults.push(...results)

    if (errors.length === 0) {
      return ok(allResults)
    }

    if (attempt === maxRetries) {
      return err({
        message: `${errors.length} items failed after ${maxRetries} retries`,
        failedItems: errors
      })
    }

    // Retry only failed items
    currentItems = errors.map(e => e.item)
    console.log(`Retrying ${currentItems.length} failed items (attempt ${attempt + 1})`)
  }

  return err({ message: 'No attempts ran', failedItems: [] })
}
```

## Progress Tracking

### Console Progress Bar

```typescript
import { batch, mapAsync } from '@ontologyio/receta/async'

async function processWithProgress<T, U>(
  items: T[],
  fn: (item: T) => Promise<U>
) {
  const total = items.length
  let done = 0

  return batch(items,
    (group) => mapAsync(group, async (item) => {
      const result = await fn(item)
      done++
      const percent = ((done / total) * 100).toFixed(1)
      const bar = '█'.repeat(Math.floor(done / total * 40))
      const empty = '░'.repeat(40 - bar.length)
      process.stdout.write(`\r[${bar}${empty}] ${percent}% (${done}/${total})`)
      return result
    }),
    { batchSize: 100 }
  )
}
```

### Structured Progress Reporting

```typescript
interface ProgressReport {
  stage: string
  completed: number
  total: number
  percent: number
  estimatedTimeRemaining: number
  errors: number
}

class BatchProgressTracker {
  private startTime = Date.now()
  private completed = 0
  private errors = 0

  constructor(
    private total: number,
    private stage: string,
    private onUpdate: (report: ProgressReport) => void
  ) {}

  update(completed: number, errorOccurred = false) {
    this.completed = completed
    if (errorOccurred) this.errors++

    const elapsed = Date.now() - this.startTime
    const rate = completed / elapsed
    const remaining = this.total - completed
    const estimatedTimeRemaining = remaining / rate

    this.onUpdate({
      stage: this.stage,
      completed,
      total: this.total,
      percent: (completed / this.total) * 100,
      estimatedTimeRemaining,
      errors: this.errors
    })
  }
}

// Usage
async function processWithTracking<T, U>(
  items: T[],
  fn: (item: T) => Promise<U>
) {
  const tracker = new BatchProgressTracker(
    items.length,
    'Processing items',
    (report) => {
      console.log(`${report.stage}: ${report.completed}/${report.total}`)
      console.log(`ETA: ${Math.round(report.estimatedTimeRemaining / 1000)}s`)
      if (report.errors > 0) {
        console.log(`Errors: ${report.errors}`)
      }
    }
  )

  let completed = 0

  return batch(items,
    (group) => mapAsync(group, async (item) => {
      const result = await tryCatchAsync(() => fn(item))
      completed++
      tracker.update(completed, isErr(result))
      return result
    }),
    { batchSize: 100 }
  )
}
```

## Summary

### When to Use Batching

Use `batch()` when:
- Processing large datasets (>100 items)
- Calling rate-limited APIs
- Managing memory usage
- Need progress tracking
- Want controlled concurrency

### When to Use Polling

Use `poll()` when:
- Waiting for async jobs to complete
- Monitoring external system status
- Processing webhooks/callbacks
- Checking for data availability
- Long-running operations

### Best Practices

1. **Start conservative**: Small batch sizes, low concurrency
2. **Monitor and adjust**: Track performance, optimize iteratively
3. **Handle errors gracefully**: Continue on error, retry failed items
4. **Respect rate limits**: Add delays between batches
5. **Track progress**: Keep users informed on long operations
6. **Test edge cases**: Empty arrays, all failures, timeouts
7. **Use backoff where it exists**: `retry` has it, while `poll` waits a fixed `interval`
