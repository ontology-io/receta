## Root Decision Tree: Which Module Do I Need?

<DecisionTree layout="cards">

What are you trying to do?

- Handle operations that can **fail**?
  - Need detailed error information? → [`result`](./result/index.mdx)
  - Just care if value exists or not? → [`option`](./option/index.mdx)
- Work with **async** or promise operations?
  - Control concurrency or timing? → [`async`](./async/index.mdx)
  - Error handling? → [`async`](./async/index.mdx) + [`result`](./result/index.mdx)
- **Filter** or test values?
  - Simple yes/no checks? → [`predicate`](./predicate/index.mdx)
  - Collect multiple errors? → [`validation`](./validation/index.mdx)
- Work with **collections** (arrays, lists)?
  - Basic operations (map, filter)? → Remeda directly
  - Hierarchical grouping or nesting? → [`collection`](./collection/index.mdx)
  - Change detection or diffing? → [`collection`](./collection/index.mdx)
  - Pagination? → [`collection`](./collection/index.mdx)
- Work with **objects**?
  - Simple pick/omit/mapValues? → Remeda directly
  - Flatten/unflatten nested objects? → [`object`](./object/index.mdx)
  - Safe nested access? → [`object/getPath`](./reference/object.mdx#getpath)
  - Deep merging or validation? → [`object`](./object/index.mdx)
- Work with **strings**?
  - Format/transform (case, slugify)? → [`string`](./reference/string.mdx)
  - Validate (email, URL)? → [`string/isEmail`](./reference/string.mdx#isemail), [`isUrl`](./reference/string.mdx#isurl)
  - Sanitize (HTML escape, trim)? → [`string/escapeHtml`](./reference/string.mdx#escapehtml), [`trim`](./reference/string.mdx#trim)
- Work with **numbers**?
  - Format (currency, percentage, bytes)? → [`number`](./reference/number.mdx)
  - Validate or clamp ranges? → [`number`](./reference/number.mdx)
  - Parse safely from string? → [`number/fromString`](./reference/number.mdx#fromstring)
- **Optimize** performance?
  - Cache function results? → [`memo`](./memo/index.mdx)
  - Deduplicate async calls? → [`memo/memoizeAsync`](./reference/memo.mdx#memoizeasync)
- **Update** nested immutable data?
  - Simple property updates? → [`object/setPath`](./reference/object.mdx#setpath)
  - Complex compositional updates? → [`lens`](./lens/index.mdx)
- **Sort** collections?
  - Simple ascending/descending? → Remeda `sortBy`
  - Multi-level or custom sorting? → [`compare`](./compare/index.mdx)
- Transform or compose **functions**?
  - Conditional logic (if/switch)? → [`function/ifElse`](./reference/function.mdx#ifelse), [`cond`](./reference/function.mdx#cond)
  - Compose multiple functions? → [`function/compose`](./reference/function.mdx#compose)
  - Partial application? → [`function/partial`](./reference/function.mdx#partial)
  - Memoize? → [`function/memoize`](./reference/function.mdx#memoize)

</DecisionTree>

## Quick Reference by Problem Type

Entries read as `module/function`: `result/tryCatch` is `tryCatch` from `@ontologyio/receta/result`.

### Error Handling
- **Known to fail, need error details** → `result/tryCatch`, `result/map`, `result/flatMap`
- **Optional/nullable values** → `option/fromNullable`, `option/map`
- **Form validation (multiple errors)** → `validation/schema`, `validation/validateAll`

### Async Operations
- **Retry failed requests** → `async/retry`
- **Timeout promises** → `async/timeout`
- **Process array in parallel** → `async/mapAsync`
- **Rate limiting** → `async/debounce`, `async/throttle`

### Data Transformation
- **Filter arrays** → `predicate/where`, `remeda/filter`
- **Transform nested objects** → `object/mapValues`, `lens/over`
- **Group hierarchically** → `collection/nest`
- **Detect changes** → `collection/diff`

### Formatting
- **Currency** → `number/toCurrency`
- **Dates** → Use a date library (out of scope for Receta)
- **File sizes** → `number/toBytes`
- **URLs/slugs** → `string/slugify`

### Type Safety
- **Type guards** → `predicate/isString`, `predicate/isNumber`, etc.
- **Runtime validation** → `validation/schema`, `object/validateShape`
- **Narrowing unions** → `result/match`, `option/match`

## Module Relationships

<ModuleMap>

`Result` and `Option` are always available, and `Validation` is like `Result` with error accumulation. Predicates feed `where`, which feeds a filter. `Lens` builds on `Object` for immutable updates, next to `Collection` and `String`. `Memo` and `Async` cover performance.

</ModuleMap>

## Decision Tree Usage Tips

1. **Start broad, narrow down**: Use this root tree first, then read the module's guide
2. **Multiple modules**: Complex problems often need 2-3 modules together
3. **Remeda first**: If Remeda has it, use Remeda. Receta builds on top
4. **Result by default**: When in doubt about error handling, use Result pattern
5. **Option for nullability**: If you'd check `value != null`, use Option instead
